# 文档维护 / Documentation maintenance

[中文入口](README.md) · [English entry](README.en.md)

## 中文

- README、文档导航、使用指南、开发说明与安全说明成对更新中英文。行为、命令、权限和风险边界保持一致，页首互链。
- 详细历史材料可暂留中文，但英文导航须标明语言。不要把文档翻译写成应用UI已国际化。
- 先描述当前流程，再链接需求和证据；旧方案注明适用阶段，不将历史测试数量当最新结果。
- 每张流程截图关联步骤、来源脚本、原拍摄日期、数据性质与验证边界；原图保留本地演示标识。不同用例不伪装成连续生产流程。
- 演示数据独立构造，不从真实家庭截图抄数值到测试。不得提交真实账本、令牌、邀请链接或生产回执。
- 只更新文档时检查本地链接、图片、双语对应与差异；涉及安全结论时重跑相关既有检查。受阻项写blocked/not_run，不用旧证据补成通过。

## English

- Update Chinese/English pairs for the README, index, user guide, development guide, and security policy. Keep behavior, commands, permissions, and risk boundaries aligned, with reciprocal links.
- Historical references may remain Chinese if English navigation labels them. Translating documents does not internationalize the application UI.
- Describe current workflows before linking requirements and evidence. Label historical stages; old test counts are not current results.
- Map every screenshot to a step, source script, original capture date, data type, and verification boundary. Keep the local-demo banner; separate test scenarios are not a continuous production session.
- Construct independent synthetic data rather than copying personal screenshots into fixtures. Never commit real ledgers, tokens, invitations, or production receipts.
- For documentation changes, verify links, images, translation pairs, and diffs. Rerun relevant existing checks for security claims. Record blocked/not_run honestly rather than treating old evidence as a new pass.
