# 两个助手的API Key流式体验

用户要求继续使用新配置的API Key，stream输出；OAuth只解释能力，不切换接入。保留既有家庭鉴权、资产与预算审批门禁，不修改已导入资产。

消费助手：自动识别旅行/购物/餐饮/一般消费。财务依据和只读工具在后台读取，不铺开查询节点或原始资金依据。分析文字以SSE增量呈现；旅行生成可编辑逐日行程及交通/酒店/餐饮清单，数量与单价改动实时重算预算，删除行程同步移除关联费用；购物显示有来源的同款规格/价格/运费等比价参考。本人核对清单后复核，最终确认才创建预算。

投资助手：资产、负债、目标、预算、持仓、近期消费与行情研究属于同一次分析的后台节点，只展示持续生成的分析、数据时间、必要缺口和最终来源，不显示逐工具清单或另一个理财研究交互。

已复现：生产research调用上游200后在model_stream阶段约62039ms失败；当前模型读取超时60秒，错误误归类为格式校验。消费研究前端未请求SSE，等待完整JSON；投资虽用SSE但显示工具节点。千问qwen3.8-max默认深思考且默认xhigh，结构化方案应使用该提供方支持的非思考JSON模式，并提供合理的流读取上限。传输200不代表应用生成成功；区分超时、截断、JSON及来源错误，日志仅含安全错误码/阶段，不记录账本或上游正文。

采用复用现有research/advisor/investment接口的SSE事件流，不新建另一套对话/另一个研究面板。现有OAuth适配保留stream兼容性，但实际联调以配置的千问API Key为准。检索仍仅发送公开关键词；移除手工必填关键词后由服务端从明确的目的地/商品/证券实体生成，不把完整私密问题或账本送搜索引擎。

验收：真实延迟SSE首段在完整模型结束前可见；上游200后超时分类正确；截断不入库；财务节点不出现在页面；行程关联费用与总预算响应调整；商品来源不伪造；投资一个问题完成全部后台读取及流式结论。隔离模型E2E与两个真实线上场景分别报告。
