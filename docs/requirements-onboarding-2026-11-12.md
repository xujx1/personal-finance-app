# 家庭财务建档工作流需求

用户希望通过ChatGPT循序了解家庭现状，避免初次进入网站只有空数据。新增第六个工作流“家庭财务建档”，网站负责核对、保存和展示。以下补充此前MCP迁移需求。

| 编号 | 需求 | 实现口径 |
| --- | --- | --- |
| O001 | 自适应访谈 | 先读取真实家庭上下文与已有草稿，每轮只问一两项关键缺失；支持未知、跳过、稍后继续，不强制完整流水或所有目标。 |
| O002 | 首次使用入口 | 空家庭总览展示开始建档；已有家庭从账户菜单“工作流集成”继续。六步显示成员、类别、余额、目标、固定收支、可选历史状态。通用导航清空旧任务提示，明确日历/资产任务仍保留上下文。 |
| O003 | 成员与家庭权限分开 | ChatGPT仅整理记账昵称，网站采用后创建未关联登录的财务档案，不发邀请、不创建账号或授予访问。现有登录与家庭邀请政策保持不变。 |
| O004 | 资产类别预置与补充 | 保留14类基础目录，可从ChatGPT提交新增类型配置草稿；不删除或覆盖既有类型，性质、目标分组和重叠仍由服务器验证。 |
| O005 | 已有资产负债 | 沿用asset草稿，逐项核对实际持有、归属、币种和余额日期。开账不是新收入或新买入，不扣银行现金；真实核实为零的银行账户允许登记且不生成零额分录。未知不能填零。 |
| O006 | 用户自己的目标 | 新setup草稿可设置自选范围、目标金额、可选月积累和日期；元转分严格计算，不使用演示目标替用户决定。更新已有目标时展示并核对完整替换范围。未确认目标的首页不显示默认400万元为用户目标。 |
| O007 | 明确固定收支 | 没有多月历史也可按用户明确陈述提交固定规则草稿；账户、成员、金额、日期核对后保存，从今天或未来生效，默认不自动记账，不伪造过去工资或贷款扣款。贷款本金/份额仍逐期核实。 |
| O008 | 可选历史 | 采用真实现金账户后可补录实际历史。完整分页排重；已包含余额必须匹配metadata.asOf和snapshotDate，只补历史不二次扣现金。覆盖不明不提交。 |
| O009 | 有限配置草稿 | submit_finance_draft增加kind=setup，分members/asset_types/goals/recurring四类。严格字段、数量、实际家庭引用、相关依据指纹和版本控制；提交不落正式配置，网站采用后才生效。只读、非成员、撤销成员不能写入。 |
| O010 | 六工作流安装与兼容 | npm入口升级1.2.0，安装六入口；使用时读取最新正文。现存五工作流的私有内容不丢失，当前读取只补缺少的建档正文，明确历史版本仍保持原五份内容。网站不恢复维护/下载/备份UI。 |

## 引导顺序与边界

按实际缺项而非硬性问卷顺序：先确认需要的昵称和归属，再明确现有余额及快照日期、类别、目标和固定安排，最后可选历史。每段采用后重新读取真实ID再提交依赖项；不凭空引用新成员或账户。已有部分数据从缺项继续，不初始化覆盖。

资产本金、负债和币种单列；目标范围不能重叠。计划买入、预计工资与尚未付款的预算不记作实际。问题、图片及共享内容中未知数值不补造，不收集密码、API Key或完整银行账号，不把家庭资料送到搜索引擎。

本轮链接示例无法直接抓取；实现依据用户在对话中明确表达的分步引导意图，不把无法读取的共享页当已核实资料，也不导入历史家庭数据到其他用户。

## 使用入口

网站：空家庭首页“开始家庭财务建档”，或账户菜单 → 工作流集成 → 在ChatGPT继续建档。ChatGPT可直接说“帮我建立家庭财务档案，先读取已有数据，按步骤问我”。返回网站核对每段草稿，再继续下一段。

当前Skill不创建登录家庭或改变邀请政策；没有权限时仍需网站现有ChatGPT登录与家庭邀请。用户的记账昵称不会使对方自动加入。

## 验证结果

587项代码/接口测试、类型检查通过。七套端到端合计75项通过：建档15、迁移17、npm安装与日历10、月报6、资产类型9、交易安全10、取消刷新8；0页面脚本错误、0意外外网请求。

建档15项在独立家庭真实HTTP、SQLite和Chrome上执行，ChatGPT结果为明确结构化夹具，覆盖从空家庭到成员/类别/资产/贷款/目标/固定规则和已含余额历史。另有独立Skill三轮基线与四场景正向模拟，未调用真实用户MCP写入，不将此记为真人ChatGPT会话推理测试。

独立审查发现两个P2：固定规则切换类型残留贷款/投资字段，旧任务提示使建档入口不可达。已修复并定向复查，浏览器回归覆盖。默认脱敏、既有家庭隔离与历史归档不受影响。
