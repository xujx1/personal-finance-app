# 停用登录，保留记账成员

**中文** · [English](MEMBER-LOGIN-RETIREMENT.en.md)

管理员在“家庭管理”中选择其他登录成员的“停用登录并保留记账成员”，先下载并私下保存完整备份，再确认迁移。该操作只停用本站家庭访问，不删除 OpenAI 账号，也不把两个人的财务归属合为一人。

备份以单次一致性读取保存当前家庭活动账本中的所有资产、流水、分录、文档、审批、月报、审计和请求回执，以及账本、家庭、成员和邀请元数据。它不使用页面的近期流水上限，也不使用会截断长字段的数据库查看器。其他家庭、运行时凭据和附件文件本体不导出；附件及图片原引用保留，迁移不改动存储中的文件。其他历史恢复数据集不属于本次活动账本逻辑备份。

备份包含财务资料，须放在私人目录，不上传 GitHub。离线检查与恢复演练：

```sh
node scripts/verify-member-retirement-backup.mjs /private/path/before.json
```

验证器在独立内存数据库重建原始行、检查外键及借贷平衡，不连接或恢复生产数据库。两份备份可用于迁移后核对：

```sh
node scripts/verify-member-retirement-backup.mjs /private/path/before.json /private/path/after.json
```

迁移必须提交当前完整备份的校验值。备份后账本或成员变化时拒绝执行，须重新备份。归属、审批兼容、审计和登录停用原子执行；相同迁移重试返回原回执。

- 当前资产转至独立记账档案，原登录身份作为历史归属别名保留。已过账流水和分录不改写；历史推断归属在更新前冻结。
- 已通过、已拒绝的现行审批保留原决定、原投票人与时间；待审批计划清空当前轮投票，由剩余有效登录成员重新确认。旧审批内容完整保留在计划的迁移历史中。
- 后续修改计划内容或改变家庭登录成员，仍遵循正常重新审批规则；迁移不会替任何人同意预算。
- 记账档案不提供登录或审批权限。被停用身份的旧会话、MCP和财务接口失去家庭访问，历史姓名及审计身份保留。

数据库逻辑备份不等同于托管数据库全量快照，离线恢复演练也不等同于生产恢复。生产恢复须使用受控数据库操作，不能把恢复文件当成可公开导入接口。
